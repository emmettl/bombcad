# Releasing 0.5.0: the checklist

Not a release. The steps to take once the user says go, so that 0.5.0 is quick to make. The
procedure itself is [Releasing](../releasing.md); the notes are the [0.5.0 draft](0.5.0.md).

## Before building

0. **Must fix: shells drawn streaked.** f154b61d (18 October 2026, 00:16) grew `ShellElement` to
   48 bytes, and Render.metal's mirror of it stayed at 40, so every shell scene since has been
   drawn with its curtain walls and glass stretched hundreds of metres; the runs themselves are
   sound. The steel session is pushing the fix with a test of the two layouts. Nothing is built
   until it is on `main` and the office, terraced, hub and warehouse snapshots
   (`blastbench snapshot --preset office|terraced|hub|warehouse`) render cleanly. Every image of
   a shell scene taken since f154b61d is re-taken: of the docs', `transport-hub.png` (taken at
   3cc08e4a); `beirut-2020.png` and `new-district.png` show no shells. Fixed in de75bae1; the
   guard is `RenderLayoutTests` (the renderer's `ShellMeshNode` and `ShellMeshElement` against
   Shell.metal's, field by field), which the full check runs: a red one there stops the build.
   **Done, 18 October:** on de75bae1 the office, terraced, hub and warehouse render as before the
   streaks at 50 and 250 ms (`--dx 0.5 --time 0.3 --frames 0.05,0.25`; StudioData
   `bombcad/release-0.5.0/render-check/`), the office as `office-tower.png` was drawn.
1. **The commit.** The newest commit on `main` that has passed `~/.local/bin/gpu-slot make
   check-anywhere`, with every push meant for 0.5.0 on it and folded into the draft notes and the
   [standing](../standing.md). Write it down: the build, the notes and the tag all name it.
2. **The notes.** Read [0.5.0.md](0.5.0.md) against `git log v0.4.0..<commit>`, and check the
   table of harnesses [still on the balloon start](../validation.md#still-on-the-balloon-start)
   against what the notes say was rerun. Each feature has its
   standing, from the scene's own (`blastbench snapshot --preset <name> --standing` prints it; the
   app's badges show it). Have them reviewed independently, as 0.2.0's to 0.4.0's were.
3. **The snapshots.** Re-take, from that commit's release build, the pictures of the samples whose
   look a default changed since they were made (settling under self-weight, glazing that vents,
   failed walls that open, refined façades, the mapped start's air), and check each still says
   what its page says:
   - `office-tower.png`, `office-tower-3s.png` (`--preset office`), only once step 0's fix is in;
   - `large-panel-gas-700ms.png`, `large-panel-street-1500ms.png`, `large-panel-street-4000ms.png`
     (`panel-gas`, `panel-street`);
   - `process-plant-overview.png`, `process-plant-buildings.png` (`plant`);
   - `transport-hub.png` (`hub`).

   Each is `blastbench snapshot --preset <name> --time <s> --out <png>`, inside `gpu-slot`, one at
   a time. The page beside each gives the time and the view.
4. **The version.** In `Support/Info.plist`, `CFBundleShortVersionString` 0.5.0 and
   `CFBundleVersion` 11, committed on a branch from the chosen commit.

## Building

5. **A quiet window.** Ask the sessions running GPU work to pause (`kill -STOP`) for the build,
   then tell each when it is over. The app's tests no longer depend on timing, but a loaded Studio
   once failed a release's checks.
6. **Build:**
   ```bash
   export BOMBCAD_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
   export BOMBCAD_NOTARY_PROFILE="BombCAD-notary"
   make release-check
   ~/.local/bin/gpu-slot make release
   ```
   It takes the slot kept for checks. If `notarytool` reports no `BombCAD-notary` profile, the
   user runs `make release` in Terminal.app instead. Never run two releases at once on one
   checkout.
7. **Verify the ZIP** from a fresh expansion: `stapler validate`, `codesign --verify --deep
   --strict`, `spctl -a -vv` (Notarized Developer ID), the licence and every resource bundle inside,
   and a document opened in the packaged app (`make app-smoke` does it in the release; open one by
   hand too). Record the build in [Releasing](../releasing.md), under "Checked so far".

## Publishing, only when the user confirms

8. **The user confirms in this chat, directly:** first that the build may be made (steps 5–6), and
   then, having seen the verified candidate, that it may be published. A relayed approval is not
   enough.
9. **Publish:** fill in the notes' version, build and commit, and take off the draft line. Push
   after `gpu-slot make check-anywhere`. Tag the build commit (`git tag v0.5.0 <commit>` and `git
   push origin refs/tags/v0.5.0`), then run `gh release create v0.5.0 --verify-tag --latest` with
   the ZIP, its `.sha256`, its `.json` and the notes. Download the release back to StudioData and
   check its checksum.
10. **Homebrew:** `python3 Scripts/update-homebrew-tap.py 0.5.0`, then `brew update` and
   `brew audit --cask --strict --online emmettl/tap/bombcad` ([Releasing](../releasing.md#after-publishing-the-homebrew-cask)).
